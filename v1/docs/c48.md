# C48 Version-1 Language Contract

This is the Phase-11 working contract for C48. The immutable authority is
ZX-UX Architecture REV17 Section 25, with REV08 defining the Phase-11 work and
acceptance sequence. The corrected
`docs/04-C48 Language Specification Rev 0.11.docx` and the pinned Python SDK
are mandatory reconciliation inputs; neither overrides REV17.

## Supported language surface

C48 version 1 supports exactly these language families:

- `void`, `char`, `unsigned char`, `short`, `unsigned short`,
  `int`, `unsigned int`, and the platform-native five-byte `float`;
- pointers and arrays;
- functions and restricted fixed-argument prototypes;
- local variables, global variables, file-scope static storage, and `extern`;
- `if/else`, `while`, `do/while`, `for`, `break`, `continue`,
  and `return`;
- `sizeof`, unary operators, arithmetic, bitwise operators, comparisons,
  logical operators, pointer dereference/address-of, indexing, and calls;
- string literals and character literals;
- simple constant scalar initializers and one-dimensional constant array
  initializers;
- casts among integer scalar types and between integer scalar types and
  `float`.

The fixed version-1 operator set is `=`, `+ - * / %`, `++ --`,
`<< >>`, `< <= > >= == !=`, `& | ^ ~`, `&& || !`,
address/dereference `& *`, indexing/call `[] ()`, and unary `+ -`.

Compound assignments, the conditional `?:` operator, and the comma operator
are deferred.

The following are not version-1 C48 features unless a later canonical
architecture revision says otherwise: `double` as a distinct format from C48
`float`, `long long`, variable-length arrays, complex initializers,
variadic functions, function pointers, `switch/case`, `struct/union`,
complex preprocessor macros, optimizer passes requiring large IR, and full ISO
C conformance. `long` is unsupported.

## Exact data model

| Type | sizeof | alignment |
| --- | ---: | ---: |
| `char`, `unsigned char` | 1 | 1 |
| `short`, `unsigned short` | 2 | 2 |
| `int`, `unsigned int` | 2 | 2 |
| pointer | 2 | 2 |
| `float` | 5 | 1 |
| `long` | unsupported | unsupported |

Plain `char` is unsigned; `signed char` is not a distinct version-1 type.
Arrays have no inter-element padding beyond element `sizeof`; array stride is
exactly `sizeof(element)`. Globals and locals use only the minimum alignment
padding in the table. `sizeof` produces `unsigned int`. Signed `short`
and `int` are two's-complement. `void` is valid as a function return type
and pointer base type, not an object type.

Integer addition, subtraction, multiplication, unary minus, and left shift wrap
modulo operand width. Signed division truncates toward zero and signed remainder
has the dividend's sign. Division or remainder by zero terminates the C48
process with status 1 through runtime error handling. Signed right shift is
arithmetic; unsigned right shift is logical. Shift counts use the low 3 bits
for 8-bit operands and low 4 bits for 16-bit operands. Pointer arithmetic
scales by pointed-to `sizeof`; subtraction within the same array/object yields
a signed 16-bit element count. Ordering or subtraction of unrelated pointers
is outside the portable C48 contract.

C48 `float` is the Sinclair ZX Spectrum ROM-compatible five-byte format, not
IEEE-754 32-bit float. Floating operators and math library calls lower through
the controlled kernel/runtime ROM-calculator service.

## Functions and ABI

A version-1 prototype uses only supported scalar/pointer types, a fixed argument
count, and no variadic marker. Prototype and definition types must match exactly.
Program entry is exactly `int main(void)` or
`int main(int argc, char **argv)`.

The sole externally linkable convention is `C48_REGCALL`. Each
scalar/pointer argument occupies one 16-bit call slot: HL, then DE, then BC,
then right-to-left 16-bit stack words. Eight-bit `char` arguments are
zero-extended. The caller removes stack arguments. SP is even at every C48 call
boundary.

A `float` argument is a pointer to caller-owned five-byte storage. A function
returning `float` receives a hidden result pointer in HL, shifting user
arguments to DE, BC, then stack, writes the five-byte result there, and returns
the same pointer in HL. Ordinary return locations are L for 8-bit scalar and HL
for 16-bit scalar/pointer.

AF, BC, DE, and HL are caller-clobbered. IX is callee-preserved when used. IY is
OS/ROM-reserved. The alternate register bank is OS-private.

## Preprocessor boundary

Version 1 supports object-like `#define`, one-level local
`#include "name"`, and built-in `#include <c48.h>`. Macro functions,
recursive include, conditional preprocessing, token pasting, stringification,
and a full ISO preprocessor are deferred.

## Source, compiler, and object contract

Identifiers are case-sensitive and limited to 15 visible characters; longer
identifiers are errors and are never silently truncated or hashed. The native
compiler command is lower-case `cc`, consumes one C-typed input object, and
atomically emits REV17 OBJ1 Z80 code. The Python SDK's deterministic C48B1
format is a host reference format only; it is not OBJ1, MEX1, or target code.

The compiler pipeline is streaming and memory-bounded: source stream, lexer,
recursive-descent parser, bounded expression tree/direct emission, symbolic
Z80 emitter, then OBJ1 writer. It must not require a whole-program AST.
Expression trees are bounded and released promptly. The complete native
compiler process-owned live footprint has a release target of at most 20 KiB.

Portable version-1 code generation emits documented Z80 instructions only;
undocumented opcodes are forbidden. Selected later Phase-11 steps prove the
required Z80 idioms and cases where they must not be used.

## Reconciliation result

P11.01 reconciled REV17, the complete C48 DOCX, and SDK commit
`84d144de2721cda5075c3a6610a422663b5e2f77`. The DOCX contained stale
REV11/REV02 authority references; those references were corrected to REV17/REV08
without changing the intended C48 language semantics. The SDK's host-only
C48B1/VM mechanisms remain reference oracles and do not substitute for native
OBJ1, C48_REGCALL, target ROM floating-point, resource, or runtime proof.

Where REV17, this working document, the corrected DOCX, the pinned SDK, or later
native behavior disagree, REV17 controls. Every known difference is recorded in
`v1/tests/compiler/sdk-reference/SDK-PROVENANCE.md`; P11.01 closes with zero
unresolved three-way discrepancies.


## P11.03 native preprocessor freeze

The native preprocessor runs before lexical parsing and exposes only the REV17
version-1 surface. Object-like macro definitions use exact case-sensitive names
of at most 15 visible characters. The initial target freezes a 16-entry macro
table and 32-byte bounded replacement representation; overflow fails before
committed output changes.

Quoted includes accept one portable 1..10-byte basename from the current working
directory. They resolve through ordinary ZX-UX SYS_STAT/SYS_OPEN and stream
OBJ_C or OBJ_TXT bytes through the same 64-byte compiler source window; no
aggregate include copy is created. An include seen at include depth one is
rejected, also blocking cycles.

The c48.h system header is compiler-resident, injected through the same bounded
source stream, and performs no object or tape lookup. P11.41 later freezes the
complete public declaration set without changing this delivery rule.

Function-like macros, conditional preprocessing, token paste, stringification,
nested/recursive includes, unknown angle-bracket headers, and a full ISO
preprocessor fail before output commit. This matches the pinned SDK
compiler/c48/preprocessor.py surface; host-only filesystem and safety mechanics
remain reference behavior rather than target ABI.

## P11.24 byte-preserving text and memory runtime

The C48 text-input boundary preserves target bytes exactly. `getchar()` reads one
byte from process stdin without case folding, translation, swallowing, or synthesis.
When stdin is `/dev/tty`, physical `CAPS SHIFT + 1` `EDIT` is returned exactly as
integer 27 / `0x1B`. Physical `CAPS SHIFT + SPACE` BREAK remains cooperative
cancellation through `E_INTR`; BREAK is never returned by `getchar()` as 27.

`putchar()` and `puts()` write through process stdout, so redirection and pipes keep
their ordinary handle semantics. `puts()` appends one line-feed byte. The compact
integer formatter is a small runtime helper only; P11.46 owns the ROM-backed floating
formatter and neither routine implies a general-purpose `printf`.

The P11.24 string/memory surface is exactly `getchar`, `putchar`, `puts`,
`strlen`, `strcmp`, `strcpy`, `strncpy`, `memcpy`, `memmove`, `memchr`,
and `memset`. `memmove` selects forward or backward block copy according to overlap;
zero-length operations do not touch memory.

The opaque pointers used by `spawn`, `wait`, `stat`, `list`,
`ioctl`, `time_get`, and `time_set` point at the packed ZX-UX records
defined by the syscall ABI. C48 version 1 has no public struct syntax, so the
header deliberately exposes those record addresses as `void *`.

These source-level types map directly to the frozen `C48_REGCALL` ABI:
ordinary scalar and pointer arguments consume one 16-bit slot; `char` and
`unsigned char` values are zero-extended; each `float` argument consumes a
slot containing a pointer to caller-owned five-byte storage; and a function
returning `float` receives the hidden result pointer described above. The
declarations are checked against the target runtime entry points and the pinned
SDK host-profile declarations where that SDK profile defines the same function.
REV17 remains authoritative for the additional ZX-UX process, object, cassette,
time, UDG, and sound surfaces.
